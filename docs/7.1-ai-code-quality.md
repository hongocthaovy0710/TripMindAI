## Introduction

Tài liệu này trình bày cách **AI hỗ trợ đảm bảo chất lượng mã nguồn (code quality)** trong
dự án TripMind AI. Sau khi hoàn thành giai đoạn lập trình (Chương 6), mã nguồn cần được
kiểm tra và cải thiện chất lượng một cách có hệ thống. AI đóng vai trò như một "người kiểm
tra chất lượng" tự động — phân tích codebase, đánh giá theo các tiêu chí chất lượng, và
đưa ra khuyến nghị cụ thể dựa trên thực tế code trong [`apps/`](../apps).

## Goals

- Đánh giá chất lượng mã nguồn TripMind AI theo các tiêu chí đo lường được.
- Dùng AI phân tích từng chiều chất lượng (readability, maintainability, reliability, security).
- Ghi lại kết quả đánh giá và khuyến nghị cụ thể từ AI.

## User Stories

### US-001: Đánh giá chất lượng tổng thể bằng AI
**Description:** Là một developer, tôi muốn AI đánh giá tổng thể chất lượng code để biết
điểm mạnh và điểm yếu cần cải thiện.

**Acceptance Criteria:**
- [ ] AI đưa ra đánh giá theo ít nhất 4 chiều chất lượng
- [ ] Mỗi chiều có điểm đánh giá và giải thích cụ thể
- [ ] Có ví dụ minh họa từ code thực tế

### US-002: Kiểm tra tính nhất quán code style
**Description:** Là một developer, tôi muốn AI kiểm tra xem code có tuân theo chuẩn thống nhất không.

**Acceptance Criteria:**
- [ ] Phát hiện chỗ không nhất quán về naming, formatting
- [ ] Đề xuất chuẩn nên áp dụng
- [ ] Cho ví dụ trước/sau

### US-003: Đánh giá khả năng bảo trì
**Description:** Là một người học, tôi muốn biết code hiện tại có dễ sửa/mở rộng trong tương lai không.

**Acceptance Criteria:**
- [ ] Đánh giá độ phức tạp các hàm/module
- [ ] Chỉ ra điểm khó bảo trì
- [ ] Gợi ý cách cải thiện

## Functional Requirements

- **FR-1:** Phân tích 4 chiều chất lượng: Readability, Maintainability, Reliability, Security.
- **FR-2:** Đánh giá từng module backend (db, auth, ai_service, main, models).
- **FR-3:** Đánh giá frontend (App.tsx, api.ts).
- **FR-4:** Tổng hợp bảng điểm chất lượng tổng thể.

## Non-Goals

- Không bàn về tái cấu trúc (thuộc 7.2) hay phát hiện code smell (7.3).
- Không đo hiệu năng runtime (load test, benchmark).

## Technical Considerations

- Chất lượng được đánh giá dựa trên static analysis — không cần chạy code.
- AI phân tích theo tiêu chí ISO/IEC 25010 (Software Quality Characteristics).
- Mã nguồn đánh giá: backend FastAPI (Python) + frontend React (TypeScript).

## Success Metrics

- Tất cả module được đánh giá ít nhất một chiều chất lượng.
- Có ít nhất 3 khuyến nghị cụ thể kèm ví dụ code thực tế.

## Open Questions

- Có nên tích hợp công cụ linting tự động (pylint, ESLint) song song AI không?

## Phụ lục A – Prompt đánh giá chất lượng mã nguồn

**Prompt gửi AI để đánh giá `apps/api/tripmind/`:**

```
Dưới đây là mã nguồn backend của TripMind AI (FastAPI + SQLite). Hãy đánh giá chất
lượng code theo 4 tiêu chí: (1) Readability — code dễ đọc hiểu không? naming, comment
có rõ không? (2) Maintainability — module có trách nhiệm rõ ràng không? coupling thấp
không? (3) Reliability — xử lý lỗi đầy đủ không? edge case có bị bỏ sót không?
(4) Security — JWT, bcrypt, ownership check đúng không? Cho điểm 1-10 mỗi tiêu chí
và giải thích bằng ví dụ cụ thể từ code.
```

### Nhận xét chi tiết theo chiều chất lượng

**1. Readability (Dễ đọc) — Điểm trung bình: 7.9/10**

> *AI nhận xét:* Code được chia module rõ ràng theo chức năng. Docstring bằng
> tiếng Việt giúp người học trong nước dễ theo dõi. Tuy nhiên, `App.tsx` gộp
> quá nhiều component vào một file duy nhất (260 dòng) — khó theo dõi khi mở
> rộng.

Điểm **tốt** — naming nhất quán, có comment:
```python
# db.py — naming rõ ràng, docstring đầy đủ
def new_id() -> str:
    """Sinh UUID dạng chuỗi làm khóa chính (giống thiết kế 5.4)."""
    return str(uuid.uuid4())
```

Điểm **cần cải thiện** — `App.tsx` quá dài, nên tách component:
```tsx
// App.tsx — 260 dòng, 3 component lớn trong cùng 1 file
// Nên tách ra: AuthForm.tsx, TripForm.tsx, ItineraryView.tsx
```

**2. Maintainability (Dễ bảo trì) — Điểm trung bình: 7.8/10**

> *AI nhận xét:* Áp dụng đúng layered architecture (5.1): config → db → auth →
> ai_service → main. Repository pattern trong `db.py` giúp thay DB dễ dàng.
> Adapter pattern trong `ai_service.py` cho phép swap LLM thật vào sau. Điểm
> trừ: `main.py` xử lý SQL trực tiếp trong endpoint thay vì qua repository.

```python
# main.py — SQL viết trực tiếp trong endpoint (coupling cao)
@app.post("/api/v1/trips", status_code=201)
def save_trip(body: TripSaveIn, uid: str = Depends(current_user_id)):
    with get_conn() as conn:
        conn.execute("INSERT INTO trips ...")  # nên đưa vào db.py
```

**3. Reliability (Độ tin cậy) — Điểm trung bình: 7.5/10**

> *AI nhận xét:* Xử lý lỗi HTTP chuẩn (400/401/404). Ownership check đúng trước
> khi sửa/xóa. Tuy nhiên `ai_service.py` thiếu xử lý khi `pool` rỗng sau vòng lặp
> lọc — có thể chia 0 khi `days > len(pool)`.

```python
# ai_service.py — logic xoay vòng phức tạp, dễ bug khi pool nhỏ
for i, act in enumerate(pool):
    if i % days == (day - 1) % max(len(pool), 1) or len(pool) <= days:
        # Điều kiện phức tạp — khó đọc, cần unit test
```

**4. Security (Bảo mật) — Điểm trung bình: 8.0/10**

> *AI nhận xét:* Điểm mạnh: bcrypt hash đúng chuẩn với giới hạn 72 byte, JWT
> có thời hạn 24h, ownership check đầy đủ trước PATCH/DELETE. Điểm yếu:
> `SECRET_KEY` có giá trị mặc định dễ đoán trong dev mode — cần cảnh báo rõ hơn.

```python
# config.py — SECRET_KEY mặc định trong dev (cần cảnh báo production)
SECRET_KEY = os.getenv("TRIPMIND_SECRET", "dev-secret-change-me")
# Khuyến nghị: thêm warning nếu đang dùng giá trị mặc định
import warnings
if SECRET_KEY == "dev-secret-change-me":
    warnings.warn("TRIPMIND_SECRET chưa đặt! Nguy hiểm trong production.")
```

## Phụ lục C – Tổng hợp khuyến nghị

| # | Vấn đề | Mức độ | Hành động đề xuất |
|---|--------|--------|------------------|
| 1 | `App.tsx` 260 dòng, 3 component chung 1 file | Trung bình | Tách thành file riêng |
| 2 | SQL trực tiếp trong `main.py` | Trung bình | Chuyển vào repository (`db.py`) |
| 3 | Logic `ai_service.py` phức tạp, thiếu test | Cao | Đơn giản hóa + thêm unit test |
| 4 | `SECRET_KEY` mặc định không có cảnh báo | Thấp | Thêm `warnings.warn` |
| 5 | Thiếu type hint trong một số chỗ của `main.py` | Thấp | Thêm return type annotation |

> **Bài học:** AI đánh giá chất lượng rất hiệu quả khi được cung cấp đầy đủ mã nguồn.
> Kết quả đánh giá **không phải là chân lý tuyệt đối** — cần con người xem xét độ ưu
> tiên và quyết định cái nào sửa trước. Điểm tổng thể **7.8/10** là nền tảng tốt để
> tiếp tục tái cấu trúc ở 7.2.
