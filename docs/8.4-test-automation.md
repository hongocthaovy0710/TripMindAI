## Introduction

Tài liệu này trình bày giải pháp và hiện thực hóa **Tự động hóa Kiểm thử (Test Automation)** trong dự án TripMind AI. Tự động hóa kiểm thử là xương sống của quy trình CI/CD (Continuous Integration / Continuous Delivery), cho phép đội ngũ phát triển chạy hàng chục đến hàng trăm ca kiểm thử trong vài giây, loại bỏ hoàn toàn thao tác kiểm thử thủ công tốn thời gian và dễ nhầm lẫn.

Trong TripMind AI, AI hỗ trợ tự động hóa kiểm thử trên các phương diện:
1. **Thiết kế Test Harness & Automation Runner:** Tự động sinh mã nguồn điều phối thực thi các suite theo marker phân tầng ([`run_tests.py`](../apps/api/run_tests.py)).
2. **Cấu hình Đường ống CI/CD:** Thiết lập GitHub Actions workflow ([`.github/workflows/test.yml`](../.github/workflows/test.yml)) để kiểm tra tự động trước mỗi commit / pull request.
3. **Thiết lập Cổng kiểm soát Chất lượng (Quality Gates):** Tự động phát hiện lỗi hồi quy (regression detection), đo lường thời gian thực thi và xuất bảng tổng kết kết quả trực quan.

---

## Goals

1. Xây dựng công cụ điều phối chạy kiểm thử tự động một lệnh (`python run_tests.py`) gom nhóm theo từng cấp độ kim tự tháp kiểm thử.
2. Thiết lập quy trình CI (Continuous Integration) qua GitHub Actions tự động cài đặt môi trường, chạy kiểm thử và báo cáo trạng thái.
3. Đảm bảo cổng chất lượng (Quality Gate): 100% các ca kiểm thử phải vượt qua (Exit Code = 0) thì hệ thống mới cho phép đóng gói triển khai.

## User Stories

### US-001: Bộ điều phối kiểm thử tự động phân tầng
**Description:** Là một developer, tôi muốn chạy toàn bộ các bài kiểm thử chỉ với một lệnh duy nhất và nhận được bảng tổng kết trực quan về số lượng suite, thời gian thực thi và trạng thái PASS/FAIL.

**Acceptance Criteria:**
- [x] Script `run_tests.py` điều phối lần lượt các bộ: Kiểm thử Đơn vị, Kiểm thử Tích hợp, Kiểm thử Hệ thống, và Ma trận Thiết kế.
- [x] Hiển thị thời gian thực thi chi tiết của từng bộ và tổng thời gian toàn hệ thống.
- [x] Trả về mã thoát (Exit code) chuẩn: `0` khi toàn bộ test pass, `1` khi có bất kỳ bài test nào thất bại.

### US-002: Tự động hóa kiểm thử trên GitHub Actions CI
**Description:** Là một DevOps engineer, tôi muốn pipeline CI tự động kích hoạt mỗi khi có code mới được đẩy lên nhánh `main` hoặc tạo Pull Request để chặn đứng code lỗi lọt vào codebase chung.

**Acceptance Criteria:**
- [x] Cấu hình file workflow `.github/workflows/test.yml`.
- [x] Cài đặt tự động môi trường Python, các dependencies trong `requirements.txt` và bộ công cụ `pytest`.
- [x] Chạy script kiểm thử tự động và thông báo trạng thái kiểm thử trực tiếp trên pull request.

### US-003: Phân tích nguyên nhân lỗi tự động bằng AI (AI Root Cause Analysis)
**Description:** Là một tester, khi một bài kiểm thử bị thất bại, tôi muốn AI hỗ trợ đọc stacktrace và đề xuất vị trí sửa lỗi nhanh chóng.

**Acceptance Criteria:**
- [x] Có prompt mẫu hướng dẫn AI phân tích log lỗi từ test runner.
- [x] Gợi ý phương án khắc phục tương ứng với mã nguồn.

## Phụ lục A – Mã nguồn Test Runner Tự động

Trích xuất từ file [`apps/api/run_tests.py`](../apps/api/run_tests.py):

```python
def main():
    suites = [
        ("8.1 Kiểm thử Đơn vị (Unit Testing)", "unit"),
        ("8.2 Kiểm thử Tích hợp (Integration Testing)", "integration"),
        ("8.3 Kiểm thử Hệ thống (System Testing)", "system"),
        ("8.5 Ma trận Thiết kế Kiểm thử (BVA & EP)", "design_matrix"),
    ]

    results = []
    for name, marker in suites:
        res = run_test_suite(name, marker)
        results.append(res)

    all_passed = all(r["passed"] for r in results)
    # Xuất bảng Markdown tổng hợp kết quả
    ...
    sys.exit(0 if all_passed else 1)
```

## Phụ lục B – Đường ống CI/CD GitHub Actions

Trích xuất từ file [`.github/workflows/test.yml`](../.github/workflows/test.yml):

```yaml
name: TripMind AI Test Automation CI

on:
  push:
    branches: [ main, master ]
  pull_request:
    branches: [ main, master ]

jobs:
  test-suite:
    name: Run Automated Test Suites
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"
      - run: |
          pip install -r apps/api/requirements.txt pytest pytest-asyncio httpx
      - working-directory: apps/api
        run: python run_tests.py
```
