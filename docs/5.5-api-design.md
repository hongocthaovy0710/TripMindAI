## Introduction

Thiết kế **REST API** cho TripMind AI: quy ước đặt tên, danh sách endpoint, định dạng
request/response, mã lỗi, xác thực và versioning. Mở rộng phần API đã phác ở 3.6, bổ
sung nhóm endpoint cho tính năng Priority (Chương 4) và ví dụ chi tiết.

## Goals

- Định nghĩa quy ước REST nhất quán (đặt tên, HTTP method, status code).
- Liệt kê đầy đủ endpoint theo nhóm (auth, trips, activities, priority).
- Chuẩn hóa định dạng response và cấu trúc lỗi.
- Định nghĩa xác thực (JWT) và versioning.

## User Stories

### US-001: Quy ước REST nhất quán
**Description:** Là một developer, tôi muốn quy ước API rõ để mọi endpoint đồng nhất.

**Acceptance Criteria:**
- [ ] Quy ước đặt tên tài nguyên (danh từ số nhiều)
- [ ] Bảng ánh xạ HTTP method ↔ hành động (GET/POST/PUT/PATCH/DELETE)
- [ ] Quy ước status code (2xx/4xx/5xx)

### US-002: Endpoint cho trips và AI
**Description:** Là một client, tôi muốn API tạo/lưu/quản lý chuyến đi.

**Acceptance Criteria:**
- [ ] `POST /trips/generate` gọi AI tạo lịch trình
- [ ] CRUD `/trips`
- [ ] Có ví dụ request/response JSON

### US-003: Endpoint cho Priority (Chương 4)
**Description:** Là một client, tôi muốn API đổi và lọc priority hoạt động.

**Acceptance Criteria:**
- [ ] `PATCH /activities/:id` đổi priority
- [ ] `GET /itineraries/:id/activities?priority=high` lọc theo priority
- [ ] Có ví dụ và mã lỗi

### US-004: Chuẩn lỗi & xác thực
**Description:** Là một client, tôi muốn cấu trúc lỗi và xác thực nhất quán.

**Acceptance Criteria:**
- [ ] Cấu trúc lỗi thống nhất (code, message)
- [ ] JWT trong header Authorization
- [ ] Versioning qua `/api/v1`

## Functional Requirements

- **FR-1:** Quy ước REST (naming, method, status code).
- **FR-2:** Bảng endpoint đầy đủ theo nhóm.
- **FR-3:** Ví dụ request/response cho các endpoint chính.
- **FR-4:** Cấu trúc response chuẩn + cấu trúc lỗi.
- **FR-5:** Xác thực JWT + versioning.

## Non-Goals

- Không mô tả GraphQL (dùng REST cho MVP).
- Không đặc tả webhook/realtime (chưa cần).

## Technical Considerations

- REST trên Express, JSON là định dạng chính.
- Tất cả endpoint (trừ auth) yêu cầu JWT hợp lệ.
- Versioning theo path `/api/v1` để dễ nâng cấp sau.

## Success Metrics

- 100% endpoint tuân theo quy ước đặt tên & status code.
- Mọi lỗi trả về theo cùng một cấu trúc.
- Client đoán được hành vi endpoint từ method + path.

## Open Questions

- Phân trang danh sách chuyến đi dùng offset hay cursor?
- Có cần rate-limit riêng cho `/trips/generate` (tốn AI) không?

## Phụ lục A – Quy ước REST

| HTTP Method | Hành động | Ví dụ |
|-------------|-----------|-------|
| GET | Đọc | `GET /trips`, `GET /trips/:id` |
| POST | Tạo mới | `POST /trips` |
| PUT | Thay thế toàn bộ | `PUT /trips/:id` |
| PATCH | Cập nhật một phần | `PATCH /activities/:id` |
| DELETE | Xóa | `DELETE /trips/:id` |

**Status code:** `200` OK · `201` Created · `400` Bad Request · `401` Unauthorized ·
`403` Forbidden · `404` Not Found · `422` Unprocessable · `500` Server Error.

## Phụ lục B – Danh sách Endpoint

### Auth
| Method | Endpoint | Mô tả | Auth |
|--------|----------|-------|------|
| POST | `/api/v1/auth/register` | Đăng ký | Không |
| POST | `/api/v1/auth/login` | Đăng nhập → JWT | Không |

### Trips
| Method | Endpoint | Mô tả | Auth |
|--------|----------|-------|------|
| POST | `/api/v1/trips/generate` | AI tạo lịch trình | Có |
| POST | `/api/v1/trips` | Lưu chuyến đi | Có |
| GET | `/api/v1/trips` | Danh sách chuyến đi | Có |
| GET | `/api/v1/trips/:id` | Chi tiết | Có |
| PUT | `/api/v1/trips/:id` | Cập nhật | Có |
| DELETE | `/api/v1/trips/:id` | Xóa | Có |

### Activities & Priority (Chương 4)
| Method | Endpoint | Mô tả | Auth |
|--------|----------|-------|------|
| POST | `/api/v1/day-plans/:id/activities` | Thêm hoạt động (mặc định medium) | Có |
| PATCH | `/api/v1/activities/:id` | Đổi thông tin/priority | Có |
| DELETE | `/api/v1/activities/:id` | Xóa hoạt động | Có |
| GET | `/api/v1/itineraries/:id/activities?priority=high` | Lọc theo priority | Có |

## Phụ lục C – Ví dụ Request/Response

**Tạo lịch trình:** `POST /api/v1/trips/generate`

```json
// Request
{ "destination": "Đà Lạt", "days": 3, "budget": 3000000,
  "preferences": ["thiên nhiên", "ẩm thực"] }
```

```json
// Response 200
{
  "success": true,
  "data": {
    "destination": "Đà Lạt", "days": 3,
    "estimated_cost": 2750000, "within_budget": true,
    "itinerary": [
      { "day": 1, "activities": [
        { "name": "Hồ Xuân Hương", "time": "08:00", "cost": 0, "priority": "high" }
      ]}
    ]
  }
}
```

**Đổi priority:** `PATCH /api/v1/activities/:id`

```json
// Request
{ "priority": "high" }
```

```json
// Response 200
{ "success": true, "data": { "id": "a1", "name": "Ăn trưa", "priority": "high" } }
```

## Phụ lục D – Cấu trúc Response & Lỗi

**Response thành công (chuẩn):**

```json
{ "success": true, "data": { } }
```

**Response lỗi (chuẩn):**

```json
{
  "success": false,
  "error": { "code": "INVALID_INPUT", "message": "Số ngày phải từ 1 đến 30." }
}
```

| Mã lỗi | HTTP | Ý nghĩa |
|--------|------|---------|
| `INVALID_INPUT` | 400/422 | Dữ liệu không hợp lệ |
| `UNAUTHORIZED` | 401 | Chưa đăng nhập / token sai |
| `FORBIDDEN` | 403 | Không có quyền truy cập tài nguyên |
| `NOT_FOUND` | 404 | Không tìm thấy |
| `AI_TIMEOUT` | 504 | Dịch vụ AI quá thời gian |
| `SERVER_ERROR` | 500 | Lỗi máy chủ |

## Phụ lục E – Xác thực & Versioning

**JWT trong header:**

```
Authorization: Bearer <token>
```

- Token cấp khi login, hết hạn sau 24h (có refresh token).
- Middleware xác thực chạy trước mọi route cần đăng nhập.
- **Versioning:** tiền tố `/api/v1`; thay đổi phá vỡ tương thích → `/api/v2`.
- **Ownership:** mọi thao tác trên `/trips/:id` kiểm tra trip thuộc user hiện tại (403 nếu không).
