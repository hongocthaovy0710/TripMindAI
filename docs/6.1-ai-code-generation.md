## Introduction

Tài liệu này trình bày việc **dùng AI để sinh mã nguồn (code generation)** khi hiện
thực hóa TripMind AI. Từ thiết kế ở Chương 5 (kiến trúc, database, API), AI sinh ra
code backend (FastAPI) và frontend (React) chạy được thật. Toàn bộ code minh chứng
nằm trong thư mục [`apps/`](../apps).

## Goals

- Sinh code backend & frontend từ đặc tả thiết kế Chương 5.
- Đảm bảo code sinh ra chạy được và bám sát thiết kế (schema, API, patterns).
- Ghi lại prompt và cách kiểm chứng code do AI sinh.

## User Stories

### US-001: Sinh backend từ thiết kế API & database
**Description:** Là một developer, tôi muốn AI sinh code backend từ thiết kế 5.4/5.5 để tiết kiệm thời gian.

**Acceptance Criteria:**
- [ ] Sinh schema DB khớp 5.4 (bảng users/trips/day_plans/activities)
- [ ] Sinh endpoint khớp 5.5 (auth, trips, activities)
- [ ] Code chạy được (server khởi động, endpoint trả đúng)

### US-002: Sinh frontend từ thiết kế UI
**Description:** Là một developer, tôi muốn AI sinh giao diện React theo wireframe Chương 4.

**Acceptance Criteria:**
- [ ] Có màn hình đăng nhập, tạo lịch trình, xem lịch trình
- [ ] Có filter + đổi priority (tính năng Chương 4)
- [ ] Build TypeScript không lỗi

### US-003: Ghi lại prompt & kiểm chứng
**Description:** Là một người học, tôi muốn ghi lại prompt dùng để sinh code và cách kiểm chứng.

**Acceptance Criteria:**
- [ ] Có ví dụ prompt sinh code
- [ ] Có cách kiểm chứng (chạy thử, test endpoint)

## Functional Requirements

- **FR-1:** Sinh code backend (db, auth, ai_service, main) từ thiết kế.
- **FR-2:** Sinh code frontend (api client, App, CSS) từ wireframe.
- **FR-3:** Ghi lại prompt tiêu biểu và kết quả.
- **FR-4:** Kiểm chứng code sinh ra bằng chạy thử.

## Non-Goals

- Không bàn về code completion (thuộc 6.2) hay debugging (6.3).
- Không tối ưu hiệu năng ở mức sản xuất.

## Technical Considerations

- Backend: FastAPI + SQLite (nhẹ, không cần cài server DB).
- Frontend: React + Vite + TypeScript.
- Phần LLM thật được mock để chạy không cần API key.

## Success Metrics

- Code sinh ra chạy được ngay sau vài lần chỉnh nhỏ.
- 100% bảng/endpoint khớp thiết kế Chương 5.

## Open Questions

## Phụ lục A – Ví dụ prompt sinh code

**Prompt sinh lớp database (dẫn tới `apps/api/tripmind/db.py`):**

```
Dựa trên thiết kế database 5.4 (bảng users, trips, day_plans, activities với cột
priority), sinh module Python dùng SQLite với: hàm khởi tạo bảng (init_db), context
manager mở kết nối, hàm sinh UUID. Áp dụng Repository pattern, có ràng buộc CHECK cho
priority ('high'|'medium'|'low') và index cho truy vấn theo user và priority.
```

**Prompt sinh endpoint (dẫn tới `apps/api/tripmind/main.py`):**

```
Sinh FastAPI app với các endpoint theo API design 5.5: POST /auth/register,
POST /auth/login (trả JWT), POST /trips/generate (gọi AI service), POST /trips (lưu),
GET /trips, GET /trips/:id, DELETE /trips/:id, PATCH /activities/:id (đổi priority).
Response theo chuẩn {success, data}. Kiểm tra ownership khi thao tác trip.
```

## Phụ lục B – Trích code AI sinh (backend)

Endpoint sinh lịch trình — AI sinh từ đặc tả 5.5, gọi AI Service (Adapter pattern):

```python
@app.post("/api/v1/trips/generate")
def generate(body: GenerateIn, _uid: str = Depends(current_user_id)):
    """Gọi AI Service sinh lịch trình (mock). Chưa lưu DB — chỉ trả kết quả."""
    data = generate_itinerary(body.destination, body.days, body.budget, body.preferences)
    return {"success": True, "data": data}
```

Endpoint đổi priority — có kiểm tra ownership (bảo mật theo 5.5):

```python
@app.patch("/api/v1/activities/{activity_id}")
def update_priority(activity_id: str, body: PriorityUpdateIn,
                    uid: str = Depends(current_user_id)):
    with get_conn() as conn:
        owned = conn.execute(
            """SELECT a.id FROM activities a
               JOIN day_plans d ON a.day_plan_id=d.id
               JOIN trips t ON d.trip_id=t.id
               WHERE a.id=? AND t.user_id=?""",
            (activity_id, uid),
        ).fetchone()
        if not owned:
            raise HTTPException(404, "Không tìm thấy hoạt động")
        conn.execute("UPDATE activities SET priority=? WHERE id=?",
                     (body.priority, activity_id))
    return {"success": True, "data": {"id": activity_id, "priority": body.priority}}
```

## Phụ lục C – Kiểm chứng code do AI sinh

Sau khi sinh, code được kiểm chứng bằng cách chạy thật (không chỉ đọc):

```
✓ Đăng ký + nhận token
✓ Generate: 3 ngày, chi phí 135000, trong ngân sách
✓ Save: trip id edf4d856
✓ List: 1 chuyến đi
```

> **Bài học:** code do AI sinh **phải được chạy thử để kiểm chứng**, không tin tưởng
> mù quáng. Chính quá trình chạy thử đã lộ ra bug ở tầng xác thực (xem 6.3 Debugging).
