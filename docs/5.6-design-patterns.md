# PRD: 5.6 Mô hình Thiết kế (Design Patterns)

## Introduction

Áp dụng các **design pattern (mẫu thiết kế mức code)** vào TripMind AI để code dễ bảo
trì, dễ mở rộng và dễ test. Tài liệu chọn các pattern phù hợp bối cảnh (đặc biệt phần
tích hợp AI và tính năng Priority) kèm ví dụ code TypeScript minh hoạ.

## Goals

- Chọn các design pattern phù hợp cho từng bài toán cụ thể của TripMind AI.
- Minh hoạ mỗi pattern bằng ví dụ code TypeScript ngắn gọn.
- Giải thích lợi ích và khi nào nên dùng.
- Liên kết pattern với các thành phần đã thiết kế (5.1–5.5).

## User Stories

### US-001: Adapter/Strategy cho AI provider
**Description:** Là một developer, tôi muốn đổi nhà cung cấp AI mà không sửa nghiệp vụ.

**Acceptance Criteria:**
- [ ] Interface `LLMClient` chung
- [ ] Cài đặt OpenAI và Claude riêng
- [ ] Ví dụ code chọn provider theo cấu hình

### US-002: Repository pattern cho truy cập dữ liệu
**Description:** Là một developer, tôi muốn tách logic DB khỏi nghiệp vụ.

**Acceptance Criteria:**
- [ ] Interface repository cho Trip/Activity
- [ ] Nghiệp vụ gọi repository, không viết SQL trực tiếp
- [ ] Dễ thay/mock khi test

### US-003: Factory cho khởi tạo đối tượng
**Description:** Là một developer, tôi muốn tạo đối tượng phức tạp gọn gàng.

**Acceptance Criteria:**
- [ ] Factory tạo Itinerary từ dữ liệu AI trả về
- [ ] Ẩn chi tiết khởi tạo khỏi nơi gọi

### US-004: Các pattern hành vi (Strategy, Observer)
**Description:** Là một developer, tôi muốn xử lý linh hoạt priority và sự kiện.

**Acceptance Criteria:**
- [ ] Strategy cho quy tắc sắp xếp theo priority
- [ ] Observer cho cập nhật UI khi state đổi (khái niệm)

## Functional Requirements

- **FR-1:** Mô tả + code Adapter/Strategy cho AI provider.
- **FR-2:** Mô tả + code Repository pattern.
- **FR-3:** Mô tả + code Factory pattern.
- **FR-4:** Mô tả + code Strategy (sắp xếp priority) và Singleton (config/cache).
- **FR-5:** Bảng tổng hợp pattern ↔ vị trí áp dụng.

## Non-Goals

- Không liệt kê toàn bộ 23 GoF pattern; chỉ chọn cái dùng thực tế.
- Không tối ưu vi mô hiệu năng ở mức pattern.

## Technical Considerations

- Ví dụ viết bằng TypeScript (đồng bộ tech stack).
- Ưu tiên pattern giúp testability (Repository, Adapter).
- Tránh over-engineering: chỉ dùng pattern khi có lợi ích rõ.

## Success Metrics

- Đổi AI provider chỉ cần thêm 1 class, không sửa nghiệp vụ.
- Unit test nghiệp vụ chạy được mà không cần DB thật (nhờ Repository mock).

## Open Questions

- Có nên dùng Dependency Injection container hay tự inject thủ công?
- Observer nên tự viết hay dùng thư viện state (Redux/Zustand) ở frontend?

## Phụ lục A – Adapter + Strategy: AI Provider

Cho phép thay OpenAI ↔ Claude mà không đổi nghiệp vụ (đã nêu ở ADR-02, 5.1).

```typescript
// Interface chung
interface LLMClient {
  generateItinerary(input: TripInput): Promise<Itinerary>;
}

// Cài đặt cho OpenAI
class OpenAIClient implements LLMClient {
  async generateItinerary(input: TripInput): Promise<Itinerary> {
    // gọi OpenAI API, parse JSON -> Itinerary
    return parseItinerary(await callOpenAI(buildPrompt(input)));
  }
}

// Cài đặt cho Claude
class ClaudeClient implements LLMClient {
  async generateItinerary(input: TripInput): Promise<Itinerary> {
    return parseItinerary(await callClaude(buildPrompt(input)));
  }
}

// Chọn provider theo cấu hình (Strategy)
function createLLMClient(provider: string): LLMClient {
  return provider === 'claude' ? new ClaudeClient() : new OpenAIClient();
}

// Nghiệp vụ không phụ thuộc nhà cung cấp cụ thể
class AIService {
  constructor(private llm: LLMClient) {}
  create(input: TripInput) { return this.llm.generateItinerary(input); }
}
```

## Phụ lục B – Repository Pattern

Tách truy cập dữ liệu khỏi nghiệp vụ; dễ test bằng mock.

```typescript
interface TripRepository {
  findByUser(userId: string): Promise<Trip[]>;
  save(trip: Trip): Promise<Trip>;
}

// Cài đặt thật với PostgreSQL
class PostgresTripRepository implements TripRepository {
  findByUser(userId: string) {
    return db.query('SELECT * FROM trips WHERE user_id = $1', [userId]);
  }
  save(trip: Trip) { /* INSERT ... */ return Promise.resolve(trip); }
}

// Nghiệp vụ chỉ biết interface
class TripService {
  constructor(private repo: TripRepository) {}
  listMyTrips(userId: string) { return this.repo.findByUser(userId); }
}
```

## Phụ lục C – Factory Pattern

Dựng `Itinerary` từ JSON AI trả về, ẩn chi tiết khởi tạo.

```typescript
class ItineraryFactory {
  static fromAIResponse(json: any): Itinerary {
    const dayPlans = json.itinerary.map((d: any) =>
      new DayPlan(d.day, d.activities.map((a: any) =>
        new Activity(a.name, a.time, a.cost, a.priority ?? 'medium')))
    );
    return new Itinerary(dayPlans);
  }
}
```

## Phụ lục D – Strategy: Sắp xếp theo Priority

Cho phép đổi quy tắc sắp xếp hoạt động (theo priority, theo giờ...).

```typescript
type SortStrategy = (a: Activity, b: Activity) => number;

const byPriority: SortStrategy = (a, b) => {
  const rank = { high: 0, medium: 1, low: 2 };
  return rank[a.priority] - rank[b.priority];
};
const byTime: SortStrategy = (a, b) => a.time.localeCompare(b.time);

function sortActivities(list: Activity[], strategy: SortStrategy) {
  return [...list].sort(strategy);
}
// dùng: sortActivities(activities, byPriority)
```

## Phụ lục F – Bảng tổng hợp Pattern ↔ Vị trí áp dụng

| Pattern | Loại | Áp dụng trong TripMind AI | Lợi ích |
|---------|------|----------------------------|---------|
| Adapter/Strategy | Cấu trúc/Hành vi | Đổi AI provider (OpenAI/Claude) | Linh hoạt, dễ thay |
| Repository | Cấu trúc | Truy cập trips/activities | Tách DB, dễ test |
| Factory | Khởi tạo | Dựng Itinerary từ JSON AI | Ẩn chi tiết khởi tạo |
| Strategy | Hành vi | Sắp xếp theo priority/giờ | Đổi quy tắc dễ dàng |
| Singleton | Khởi tạo | Cache/config client | Dùng chung 1 instance |
| Cache-Aside | Kiến trúc | Cache kết quả AI (5.1/5.2) | Giảm chi phí, tăng tốc |

> **Nguyên tắc:** chỉ áp dụng pattern khi mang lại lợi ích rõ ràng (dễ thay đổi, dễ
> test, giảm trùng lặp) — tránh over-engineering làm code phức tạp không cần thiết.
