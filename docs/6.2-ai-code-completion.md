# PRD: 6.2 AI Tự động Hoàn thành Mã nguồn (Code Completion)

## Introduction

Tài liệu trình bày vai trò của **AI tự động hoàn thành mã nguồn (code completion)** —
các công cụ như GitHub Copilot, Cursor gợi ý code ngay khi gõ. Khác với code generation
(sinh cả khối/file từ mô tả), code completion hỗ trợ **liên tục, theo ngữ cảnh** trong
lúc lập trình TripMind AI.

## Goals

- Phân biệt code completion với code generation.
- Minh hoạ các tình huống completion thực tế khi viết TripMind AI.
- Nêu cách dùng completion hiệu quả và giới hạn cần lưu ý.

## User Stories

### US-001: Gợi ý hoàn thành theo ngữ cảnh
**Description:** Là một developer, tôi muốn AI gợi ý phần còn lại của dòng/hàm để gõ nhanh hơn.

**Acceptance Criteria:**
- [ ] Nêu ví dụ completion trong code TripMind AI
- [ ] Chỉ ra ngữ cảnh AI dựa vào (tên hàm, comment, type)

### US-002: Hoàn thành lặp lại có mẫu (boilerplate)
**Description:** Là một developer, tôi muốn AI hoàn thành các đoạn lặp (CRUD, mapping) để đỡ gõ tay.

**Acceptance Criteria:**
- [ ] Ví dụ completion cho code lặp (ví dụ map row → dict)
- [ ] Giải thích vì sao completion mạnh ở loại code này

### US-003: Dùng completion an toàn
**Description:** Là một developer, tôi muốn biết khi nào KHÔNG nên tin completion.

**Acceptance Criteria:**
- [ ] Nêu rủi ro (gợi ý sai, thiếu ngữ cảnh nghiệp vụ)
- [ ] Nêu cách kiểm soát (đọc lại, chạy thử)

## Functional Requirements

- **FR-1:** So sánh completion vs generation.
- **FR-2:** Ví dụ completion cụ thể trong code TripMind AI.
- **FR-3:** Hướng dẫn dùng completion hiệu quả + giới hạn.

## Non-Goals

- Không hướng dẫn cài đặt công cụ cụ thể (Copilot/Cursor).
- Không bàn debugging (6.3).

## Technical Considerations

- Completion hiệu quả nhất khi có **type rõ ràng** (TypeScript, Pydantic) và **comment mô tả**.
- Ngữ cảnh tốt (tên hàm, biến, file lân cận) giúp gợi ý chính xác hơn.

## Success Metrics

- Giảm thời gian gõ code lặp lại.
- Gợi ý khớp ngữ cảnh, ít phải sửa.

## Open Questions

- Nên bật completion toàn thời gian hay chỉ khi cần?
- Làm sao tránh phụ thuộc quá mức vào completion?

## Phụ lục A – Completion vs Generation

| Tiêu chí | Code Completion (6.2) | Code Generation (6.1) |
|----------|------------------------|------------------------|
| Phạm vi | Vài ký tự → vài dòng | Cả hàm/file/module |
| Kích hoạt | Tự động khi gõ | Yêu cầu rõ ràng (prompt) |
| Ngữ cảnh | Code đang viết xung quanh | Mô tả/đặc tả người dùng đưa |
| Ví dụ | Gõ `def verify_` → gợi ý nốt hàm | "Sinh module auth JWT" |

## Phụ lục B – Ví dụ completion trong TripMind AI

**Tình huống 1 — hoàn thành theo type + tên hàm.** Khi gõ khai báo, công cụ đoán được
phần thân nhờ tên hàm `verify_password` và kiểu tham số:

```python
def verify_password(plain: str, hashed: str) -> bool:
    pw = plain.encode("utf-8")[:72]
    return bcrypt.checkpw(pw, hashed.encode("utf-8"))   # ← phần này được gợi ý
```

**Tình huống 2 — hoàn thành code lặp (mapping row → dict).** Sau khi viết một truy vấn,
completion gợi ý ngay mẫu chuyển đổi kết quả:

```python
rows = conn.execute("SELECT * FROM trips WHERE user_id=?", (uid,)).fetchall()
return {"success": True, "data": [dict(r) for r in rows]}   # ← gợi ý phần list comprehension
```

**Tình huống 3 — hoàn thành ở frontend nhờ type.** Nhờ interface `Activity` đã khai
báo, completion gợi ý đúng các thuộc tính khi map:

```tsx
{day.activities.map((act, i) => (
  <div key={i} className="activity">
    <strong>{act.name}</strong>          {/* gợi ý act.name, act.time, act.cost... */}
    <span>{act.cost.toLocaleString("vi-VN")}đ</span>
  </div>
))}
```

## Phụ lục C – Dùng completion hiệu quả & giới hạn

**Giúp completion chính xác hơn:**
- Đặt **tên hàm/biến rõ nghĩa** (completion đọc tên để đoán ý định).
- Khai báo **type** đầy đủ (Pydantic model, TypeScript interface).
- Viết **comment mô tả** ngay trước đoạn cần gợi ý.

**Giới hạn cần lưu ý:**
- Completion **không hiểu nghiệp vụ** — có thể gợi ý đúng cú pháp nhưng sai logic.
- Dễ gợi ý **giá trị mặc định sai** (ví dụ quên ràng buộc `priority` mặc định `medium`).
- **Luôn đọc lại và chạy thử** — completion là trợ lý gõ phím, không phải người quyết định.

> **Bài học:** completion mạnh nhất với code có **type rõ** và **mẫu lặp lại**; với logic
> nghiệp vụ đặc thù thì con người vẫn phải kiểm soát.
