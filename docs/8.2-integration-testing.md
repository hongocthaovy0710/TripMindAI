## Introduction

Tài liệu này trình bày phương pháp và hiện thực hóa **Kiểm thử Tích hợp (Integration Testing) có sự hỗ trợ của AI** cho hệ thống TripMind AI. Nếu như kiểm thử đơn vị (8.1) xác minh từng hàm riêng rẽ, thì kiểm thử tích hợp kiểm chứng sự phối hợp nhịp nhàng giữa các tầng kiến trúc khác nhau:
1. **Application Layer (FastAPI Routers):** Xử lý HTTP requests, header và status code.
2. **Security & Middleware Layer:** Kiểm tra xác thực Bearer Token (JWT) và bảo vệ phân quyền sở hữu tài nguyên (Resource Ownership Isolation).
3. **Domain Layer:** Gọi dịch vụ thông minh sinh lịch trình `ai_service.py`.
4. **Data Persistence Layer (SQLite Database):** Lưu trữ thực thể quan hệ, kiểm tra ràng buộc khóa ngoại (Foreign Keys) và cơ chế xóa dây chuyền (`ON DELETE CASCADE`).

AI hỗ trợ kiểm thử tích hợp bằng cách phân tích luồng dữ liệu liên module, thiết kế kịch bản kiểm thử tương tác và phát hiện các rủi ro race condition hoặc rò rỉ dữ liệu giữa các người dùng.

---

## Goals

1. Kiểm tra sự tương tác thực tế giữa API endpoint và cơ sở dữ liệu SQLite trong môi trường cô lập.
2. Xác minh tính toàn vẹn của chu trình vòng đời chuyến đi: **Sinh lịch trình $\to$ Lưu vào DB $\to$ Truy vấn danh sách/chi tiết $\to$ Điều chỉnh độ ưu tiên hoạt động $\to$ Xóa chuyến đi**.
3. Chứng minh cơ chế bảo mật cô lập tài nguyên (Ownership Check): Người dùng B tuyệt đối không thể truy cập hoặc can thiệp chuyến đi/hoạt động của người dùng A.
4. Kiểm chứng tính toàn vẹn dữ liệu quan hệ SQLite khi xóa một chuyến đi thì toàn bộ `day_plans` và `activities` liên quan phải được dọn dẹp sạch sẽ (Cascade Delete).

## User Stories

### US-001: Kiểm thử tích hợp luồng Đăng ký & Đăng nhập
**Description:** Là một developer, tôi muốn kiểm thử tích hợp luồng Authentication để xác nhận tài khoản mới được ghi nhận vào bảng `users` và có thể đăng nhập nhận JWT token hợp lệ ngay lập tức.

**Acceptance Criteria:**
- [x] Đăng ký tài khoản thành công trả về HTTP 201 kèm token và thông tin người dùng.
- [x] Đăng ký trùng email bị từ chối với HTTP 400 và thông báo lỗi rõ ràng.
- [x] Đăng nhập sai mật khẩu bị từ chối với HTTP 401.

### US-002: Kiểm thử tích hợp vòng đời Chuyến đi và Tính năng Priority
**Description:** Là một product manager, tôi muốn kiểm thử trọn vẹn luồng từ khi AI sinh lịch trình đến khi lưu trữ và cập nhật độ ưu tiên của hoạt động theo Chương 4 (Activity Priority System).

**Acceptance Criteria:**
- [x] Endpoint `POST /api/v1/trips/generate` yêu cầu Bearer token (chặn 401 nếu thiếu).
- [x] Lưu chuyến đi vào DB tạo đầy đủ bản ghi trong bảng `trips`, `day_plans`, `activities`.
- [x] `PATCH /api/v1/activities/{id}` cập nhật đúng trường `priority` trong DB và trả về kết quả mới.

### US-003: Kiểm thử bảo mật cô lập sở hữu (Ownership Isolation)
**Description:** Là một chuyên gia an toàn thông tin, tôi muốn đảm bảo một user không thể đọc hoặc chỉnh sửa dữ liệu chuyến đi của user khác.

**Acceptance Criteria:**
- [x] User B gọi `PATCH /api/v1/activities/{act_id}` của User A bị trả về HTTP 404 (Not Found).
- [x] User B gọi `GET /api/v1/trips/{trip_id}` của User A bị từ chối với HTTP 404.

### US-004: Kiểm thử tính toàn vẹn Cascade Delete
**Description:** Là một quản trị viên cơ sở dữ liệu, tôi muốn khi người dùng xóa chuyến đi, hệ thống tự động xóa sạch các ngày lịch trình và hoạt động con để tránh dữ liệu mồ côi (orphaned data).

**Acceptance Criteria:**
- [x] Xóa chuyến đi trả về HTTP 200.
- [x] Truy vấn trực tiếp database xác nhận số lượng bản ghi tại cả 3 bảng `trips`, `day_plans`, `activities` đều trở về 0.

---

## Technical Considerations

- **Database Isolation:** Mỗi bài test hoặc suite được cấp một file database SQLite độc lập, loại bỏ hoàn toàn khả năng can nhiễu dữ liệu kiểm thử.
- **Foreign Key Support:** Bật `PRAGMA foreign_keys = ON` trong SQLite để đảm bảo cơ chế `ON DELETE CASCADE` hoạt động chính xác tương tự như PostgreSQL trên môi trường production.
- **Fixtures:** Tái sử dụng fixture `registered_user` và `second_user` để mô phỏng tương tác nhiều người dùng.

## Phụ lục B – Trích đoạn Mã nguồn Kiểm thử Tích hợp

Từ file [`apps/api/tests/test_integration.py`](../apps/api/tests/test_integration.py):

```python
def test_full_trip_persistence_and_cascading(self, client, registered_user, second_user):
    headers = registered_user["headers"]

    # 1. Sinh lịch trình & Lưu vào DB
    gen_res = client.post("/api/v1/trips/generate", headers=headers, json={...})
    save_res = client.post("/api/v1/trips", headers=headers, json=gen_res.json()["data"])
    trip_id = save_res.json()["data"]["id"]

    # 2. Kiểm tra Ownership Isolation: User B không thể sửa hoạt động của User A
    hacker_headers = second_user["headers"]
    hack_patch = client.patch(f"/api/v1/activities/{act_id}", headers=hacker_headers, json={"priority": "low"})
    assert hack_patch.status_code == 404

    # 3. Xóa chuyến đi & Xác minh Cascade Delete sạch bóng trong DB
    del_res = client.delete(f"/api/v1/trips/{trip_id}", headers=headers)
    assert del_res.status_code == 200
    with get_conn() as conn:
        assert conn.execute("SELECT COUNT(*) FROM trips WHERE id=?", (trip_id,)).fetchone()[0] == 0
        assert conn.execute("SELECT COUNT(*) FROM activities WHERE id=?", (act_id,)).fetchone()[0] == 0
```
