## Introduction

Tài liệu này trình bày phương pháp **Kiểm thử Hệ thống (System Testing) và Kiểm thử Đầu-cuối (End-to-End - E2E)** có sự hỗ trợ của AI cho dự án TripMind AI. Kiểm thử hệ thống đánh giá sản phẩm như một thể thống nhất hoàn chỉnh dưới góc nhìn của người dùng thực tế và các tiêu chuẩn phi chức năng (Non-Functional Requirements - NFR).

Trong quy trình phát triển sản phẩm với AI, AI đóng vai trò:
1. **Mô phỏng chân dung người dùng (Persona Simulation):** Đóng vai du khách thực hiện tuần tự một hành trình khép kín từ lúc phát hiện ứng dụng đến khi hoàn tất chuyến đi.
2. **Kẻ tấn công giả định (Adversarial Testing):** Thử nghiệm gửi các token bị can thiệp chữ ký số (tampered tokens), chuỗi tấn công SQL Injection và dữ liệu đầu vào không hợp lệ nhằm đánh giá sức chống chịu (robustness) của hệ thống.
3. **Đánh giá tiêu chuẩn hiệu năng (Performance SLA Testing):** Đo lường độ trễ phản hồi (latency) của API để đảm bảo trải nghiệm người dùng luôn mượt mà.

---

## Goals

1. Kiểm thử hành trình trọn vẹn của người dùng (End-to-End Traveler Journey): từ đăng ký tài khoản, kiểm tra sức khỏe hệ thống, sinh lịch trình AI, tinh chỉnh độ ưu tiên hoạt động, đến quản lý và dọn dẹp chuyến đi.
2. Kiểm tra độ tin cậy và an toàn hệ thống (System Security & Robustness) trước các tác nhân giả mạo chữ ký số JWT hoặc chèn chuỗi truy vấn độc hại.
3. Thiết lập baseline kiểm thử hiệu năng: đảm bảo thời gian phản hồi API trung bình đạt yêu cầu SLA phi chức năng ($< 500\text{ms}$).

---

## User Stories

### US-001: Hành trình người dùng du lịch khép kín (End-to-End Journey)
**Description:** Là một du khách lần đầu sử dụng TripMind AI, tôi muốn trải nghiệm luồng làm việc liên tục: tạo tài khoản $\to$ tạo lịch trình Đà Lạt 3 ngày với các sở thích thiên nhiên & ẩm thực $\to$ lưu vào kho cá nhân $\to$ đổi độ ưu tiên địa điểm tham quan $\to$ xóa chuyến đi khi hoàn thành.

**Acceptance Criteria:**
- [x] Tài khoản mới tạo nhận được token và truy cập hợp lệ vào toàn bộ tính năng.
- [x] Lịch trình sinh ra có đầy đủ 3 ngày và tổng chi phí ước tính.
- [x] Chuyến đi lưu thành công và xuất hiện trong danh mục cá nhân.
- [x] Cập nhật mức độ ưu tiên của hoạt động (`high`/`low`) được lưu trữ vĩnh viễn.
- [x] Xóa chuyến đi dọn dẹp sạch sẽ dữ liệu khỏi hồ sơ.

### US-002: Kiểm thử phòng vệ bảo mật hệ thống
**Description:** Là một quản trị viên hệ sinh thái, tôi muốn hệ thống tự động phát hiện và chặn đứng mọi token giả mạo, token không đúng định dạng và các chuỗi ký tự tấn công đặc biệt mà không làm gián đoạn dịch vụ.

**Acceptance Criteria:**
- [x] Token JWT bị thay đổi chữ ký bí mật hoặc giả mạo bị từ chối với HTTP 401.
- [x] Header Authorization không đúng chuẩn Bearer bị từ chối với HTTP 401.
- [x] Payload chứa chuỗi tấn công SQL Injection (`' OR '1'='1'; DROP TABLE...`) được xử lý an toàn bằng Parameterized Query, không gây rò rỉ dữ liệu hoặc phá hỏng schema.
- [x] Yêu cầu truy cập ID chuyến đi không tồn tại trả về lỗi HTTP 404 thân thiện.

### US-003: Đánh giá độ trễ phản hồi (API Latency SLA)
**Description:** Là một kỹ sư hiệu năng, tôi muốn đo lường thời gian đáp ứng của API trong các tác vụ liên tiếp để đảm bảo hệ thống không bị nghẽn cổ chai.

**Acceptance Criteria:**
- [x] Thực hiện 5 yêu cầu liên tiếp sinh lịch trình AI.
- [x] Thời gian phản hồi trung bình của mỗi yêu cầu phải nhỏ hơn 500ms.

## Functional Requirements

- **FR-1:** Hiện thực bộ kịch bản E2E tại [`apps/api/tests/test_system.py`](../apps/api/tests/test_system.py).
- **FR-2:** Thực hiện kiểm tra tính năng Adversarial Security Testing với JWT giả mạo và SQL Injection strings.
- **FR-3:** Thực hiện đo lường thời gian thực thi bằng `time.perf_counter()` và assert theo ngưỡng SLA.

---

## Technical Considerations

- Kiểm thử hệ thống trong ngữ cảnh backend API kiểm chứng toàn bộ chuỗi: HTTP Parsing $\to$ Authentication Handler $\to$ Pydantic Validation $\to$ Business Logic $\to$ Database SQLite $\to$ JSON Serializer.
- Không cần triển khai server vật lý mà tận dụng cơ chế in-memory transport của `TestClient` giúp tốc độ kiểm thử đạt hàng trăm request mỗi giây mà vẫn bảo đảm độ tin cậy tuyệt đối.

## Phụ lục B – Trích đoạn Mã nguồn Kiểm thử Hệ thống

```python
# Trích đoạn đo lường SLA hiệu năng trong apps/api/tests/test_system.py
def test_api_latency_under_500ms(self, client, registered_user):
    latencies = []
    headers = registered_user["headers"]

    for _ in range(5):
        t0 = time.perf_counter()
        res = client.post(
            "/api/v1/trips/generate",
            headers=headers,
            json={"destination": "Phú Quốc", "days": 3, "budget": 5000000},
        )
        elapsed_ms = (time.perf_counter() - t0) * 1000
        assert res.status_code == 200
        latencies.append(elapsed_ms)

    avg_latency = sum(latencies) / len(latencies)
    assert avg_latency < 500, f"Thời gian phản hồi quá chậm: {avg_latency:.2f}ms"
```
